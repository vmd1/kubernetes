# Flux Bootstrap (`clusters/vmd1/flux-system/`)

This folder bootstraps **FluxCD** on the `vmd1` cluster and connects it to this Git repository. It is the first thing applied to a fresh cluster; after that, Flux reconciles the rest of the repo automatically.

## Files

| File | Description |
| :--- | :--- |
| [gotk-components.yaml](gotk-components.yaml) | **Generated by `flux install` — do not edit.** Flux v2.9.4 component manifests: namespaces, CRDs, RBAC, deployments, and controllers for `source-controller`, `kustomize-controller`, `helm-controller`, and `notification-controller`. |
| [gotk-sync.yaml](gotk-sync.yaml) | **Generated by `flux bootstrap` — do not edit.** Defines the `flux-system` `GitRepository` (this repo, `https://github.com/vmd1/kubernetes`, branch `main`, synced every 1m) and the root `Kustomization` that applies `./clusters/vmd1` every 10m with pruning. |
| [kustomization.yaml](kustomization.yaml) | Kustomize entrypoint that bundles the two generated manifests above. |

## How Sync Works

1. `gotk-sync.yaml` creates a `GitRepository` named `flux-system` that clones this repository (using the SSH deploy key stored in the `flux-system` secret).
2. The `flux-system` `Kustomization` applies the contents of `./clusters/vmd1` (the entrypoint described in [../README.md](../README.md)).
3. The four layer Kustomizations (`crds-and-operators`, `nodes`, `infrastructure`, `applications`) then reconcile the [resources/](../../resources/README.md) tree.
